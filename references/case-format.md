# 案例正文：结构与文档格式规范

本规范以审定参考稿《参考案例_从50人到2人_AI编程成本豪赌.docx》为最终标准。

## 1. 总体结构（按顺序）

| # | 构件 | 要求 |
|---|---|---|
| 1 | 文档类型行 | "案例正文"，幼圆 16pt，左对齐 |
| 2 | 案例标题 | 幼圆 16pt 加粗，居中。句式参考："从五十人到两人？——一家支付公司的AI编程时代人力豪赌"（设问/悬念主标题 + 破折号副题点明行业与核心议题） |
| 3 | 摘要（Heading 2） | 一节一段，200–300 字：主角与处境、核心冲突、悬而未决的抉择；不泄结局 |
| 4 | 关键词 | 摘要段后独立一行，"关键词："加粗起头，3–5 个词以中文分号分隔 |
| 5 | 缘起（Heading 2） | 决策场景开场：具体时间、地点、主角、摆在桌面上的问题 |
| 6 | 正文若干部分（Heading 2） | "第一部分：……"至"第五部分：……"（3–6 个为宜），每部分 2–3 个小节 |
| 7 | 小节（Heading 4） | 十进制编号"0.1、1.1、1.2……"，小节标题优先用**当事人引语**（如「"我没有给员工做培训"」），其次用冲突短语 |
| 8 | 尾声（Heading 2） | 回到主角与未决选择，开放式收尾 |
| 9 | 文末标记 | "（案例正文完，全文X字）"，X 为 Word 口径字数（汉字与中文标点各计 1，连续西文/数字串计 1 词） |
| 10 | （按需）资料来源+免责声明 | 真实主体案例置于文末；化名案例的免责声明置于卷首摘要之前 |

## 2. 内容禁令

- 无讨论题、无"适用课程"（人大投稿格式：正文纯叙事，题目只出现在教学笔记）。
- 无 Exhibit 表格——数据**织入叙事**（数字+对比+后果）；确需图示时用图片，图片配加粗居中图注"图N 说明"。
- 无作者评判、无"教师/学生"元叙述、无宣传式形容词。
- 除文末字数标记外，无任何元文本。

## 3. 叙事方式（详见 narrative-style.md）

- 决策主线：主角→情境压力→备选方案→证据→决策点；编年只保留能解释决策的里程碑。
- 开场 300 字内回答：谁在决策？何时何地？桌上摆着什么？为何紧迫？
- 关键决策呈现为"当时信息不全"的进行时抉择，不用上帝视角复盘。
- 对话、引语用楷体；数字必给参照系（"四十倍差价""从4.2小时升至11.6小时"）。

## 4. 文档格式（字体与版面）

| 元素 | 格式 |
|---|---|
| 页面 | A4（21×29.7cm），上下边距 2.54cm，左右边距 2.8cm；**无页眉页脚** |
| 正文 | 西文 Times New Roman + 中文宋体，小四（12pt），1.5 倍行距，首行缩进 2 字符（24pt），两端对齐 |
| 对话/引语段 | 中文楷体 12pt，其余同正文 |
| 标题行 | "案例正文"幼圆 16pt 左对齐；案例标题幼圆 16pt 加粗居中 |
| Heading 2 | 真实 Word 标题样式（导航可用），宋体 14pt 加粗，段前间距约 10pt |
| Heading 4 | 宋体 12pt 加粗 |
| 图注 | 宋体加粗居中，"图N 说明" |
| 文末标记 | 宋体 12pt，两端对齐 |

## 5. 参考句式

- 悬念过渡："故事要从更早说起。""直到2025年。"
- 决策显形："他没有说的是，那天晚上他自己也没睡好。"
- 开放收尾：以主角的一个动作/一句回复收束（"下次见面，我带两瓶纳帕谷的红酒。我们继续争论。"），不回答问题。
