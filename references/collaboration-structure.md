# 案例正文 ↔ 教学笔记：协作结构

一对案例不是两份独立文档，而是同一教学设计的两面。写任何一份时，必须同时维护以下协作关系。

## 1. 题目从决策点生长

教学笔记的 5 道思考题不是凭空拟的，而是从案例的决策点/关键情节逐一生长：

```
案例决策点/情节  →  思考题  →  理论工具  →  参考答案
```

每题必须能在案例正文中找到对应的情节与数据锚点；案例正文的每个决策点，至多对应一道题（5 道题覆盖最重要的 5 个教学点）。映射关系用"案例问题 × 理论知识点 × 案例情节"映射表显性呈现。

## 2. 分工与隔离

| 内容 | 案例正文 | 教学笔记 |
|---|---|---|
| 叙事、场景、对话、数据 | ✓ | 仅作为分析证据被引用，不复述 |
| 讨论题/启发思考题 | ✗（人大格式） | ✓ 恰好 5 道 |
| 适用课程、教学对象 | ✗ | ✓ |
| 理论分析、参考答案 | ✗ | ✓ |
| 真实结局/后续进展 | ✗（不泄露） | ✓（可放入摘要、背景信息或专节，供教师掌握） |
| 摘要、关键词 | ✓（关键词在摘要后） | ✓（仅摘要，无关键词） |
| 免责声明/资料来源 | ✓ | 参考文献即可 |

## 3. 递进与覆盖

- 5 道题按"诊断 → 分析 → 评价 → 决策 → 延伸"递进：第 1 题诊断事实与问题成因；中间题调用理论分析机制；第 4 题落在"如果你是主角，怎么选"；第 5 题延伸到行业、伦理或未来。
- 5 题的答案合起来必须覆盖案例涉及的全部理论工具，且无两题共用同一理论。
- 题干聚焦**概念冲突**（"这类新型成本与传统人力成本有何本质差异？"），不要在题干里复述情节（"十五天三百亿Token、八万美元的账单暴露了……"这种写法已由参考稿汰换）。

## 4. 数据互引

- 答案引用案例数字时必须与正文一致（改稿时两处同改）。
- 案例中标注为演绎/未经核实的数据，笔记在教学提示或背景信息中必须向教师点明，不得当作既定事实展开分析。
- 若案例含 Exhibit 或"图N"，笔记按编号引用；案例与笔记同批修改后，逐一复核互引不断链。

## 5. 90 分钟的可执行性

- 板书计划的时间块必须与 5 道题匹配：哪些题当堂讨论、哪题留作课后，写进计划或教学提示。
- 板书计划写清每个时间块里教师做什么、学生做什么（讨论、陈述、追问、总结），禁止只写流程名词。
